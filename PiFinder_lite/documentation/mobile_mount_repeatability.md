# Mobile Mount Repeatability Validation

Issue: #48

## Purpose

`PiFinder_lite/validate_mobile_mount_repeatability.py` compares multiple
candidate mobile mount profiles and reports whether the phone-to-telescope
offset is repeatable enough to continue testing.

It is diagnostic-only. A positive report does not enable mobile IMU guidance or
PiFinder integrator input.

## Inputs

Use two or more candidate profiles generated by
`compute_mobile_mount_offset.py`. They can be passed as individual files or as a
directory:

```bash
python PiFinder_lite/validate_mobile_mount_repeatability.py \
  --input "$HOME/PiFinder_data/mobile/mount_profiles" \
  --output-dir "$HOME/PiFinder_data/mobile/repeatability"
```

## Metrics

The report compares each profile's `offset.q_phone_to_tube` quaternion against
the others and records:

- repeat profile count;
- maximum pairwise repeat error in degrees;
- median pairwise repeat error in degrees;
- source profile warnings;
- recommendation.

Default thresholds:

```text
proceed: max repeat error <= 1 deg
reject:  max repeat error >= 5 deg
otherwise: recalibrate / collect more data
```

These thresholds are conservative placeholders. They should be tuned with real
mounted night tests.

## Recommendations

| Recommendation | Meaning |
| --- | --- |
| `proceed` | Repeatability is tight enough to continue validation. |
| `recalibrate` | More captures or a better mount/reference are needed. |
| `reject` | Offset spread or source warnings make the profile unsafe to trust. |

## Field Notes

- Indoor/cloudy tests can validate stability and tooling, but not sky alignment.
- Use real night tests after the phone has been remounted.
- Capture at least two `mounted_reference` or `repeat_check` batches.
- Keep the phone physically fixed. Any clamp shift invalidates the profile.
- Do not commit generated reports with private locations or local paths unless
  they have been sanitized.
